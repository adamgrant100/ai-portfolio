My CSV checker makes data-quality checks visible: missing values, repeated records, name variations and numeric values that need a second look.

Try the experiment

Find the flags. Keep the decisions human.

Start with ten fictional records, then edit a value and run the checks again. Try changing eighty to 80, filling the missing age, or adding a duplicate row. No data is uploaded or stored by this checker.

The sample records are fictional. Review flags suggest checks; they do not prove that a record is wrong or that two people are the same.

Required headers: name,age,score, in any order. Age: whole number 0–120. Score: decimal 0–100. Extra columns are kept but not checked for missing or invalid values. Maximum 500 data records, 20 columns and 100,000 characters.

    Method

    Simple rules, explicit assumptions.

    1. Parse CSV: accept commas, quoted commas, quoted newlines, doubled quotes, LF/CRLF line endings and an initial byte-order mark. Reject malformed quoting before calculating results.
    2. Validate the schema: trim and lowercase column headers, require unique headers and the three named fields. Flag records whose field count differs from the header.
    3. Check values: whitespace-only required cells are missing. Numeric checks accept ordinary decimal notation, reject non-finite values and apply the stated example ranges.
    4. Find exact repeats: compare every parsed field, including extra columns. Preserve spaces, case and field count; flag later identical records.
    5. Find name candidates: apply Unicode NFKC normalisation, trim, collapse whitespace and lowercase. Flag groups containing different original names that share this result. Do not merge them.

    Limits

    A check is not a verdict.

    The rules suit this demonstration schema. A different dataset needs different constraints. Valid ages and scores may still be incorrect; a repeated row may represent a legitimate repeated event.

    Name normalisation cannot establish identity. It may miss spelling changes and accents, or group different people with similar names. No fuzzy matching, imputation, deletion or automatic correction is performed.

    Blank lines inside the CSV are treated as records and may be flagged. Numeric notation deliberately excludes exponents, thousands separators and percentages. The checker does not evaluate freshness, fairness, provenance or whether the data is representative.

    All analysis runs in this tab. Input is held in memory and clears on a page reload. This is a small educational tool, not a production data-validation service.
