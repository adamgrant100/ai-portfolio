02 / Coursework summaries

Evidence and artefacts

I have summarised the aims, approach and limitations of my coursework below, alongside selected code. I keep the complete written assignments and presentation in my private study archive.

Unit 2

Boolean logic in computing

I examined how Boolean logic connects hardware, software and information retrieval. Using digital-design and information-retrieval sources, I linked logic gates in processors to conditional statements in programs and the AND, OR and NOT operations used in Boolean searches.

The report’s main conclusion is that the same true/false reasoning supports decisions at several levels of a computing system. The examples explain that connection conceptually; I did not build a circuit or measure a search system. The scope is therefore an explanation of the underlying principles, with Boolean filtering considered separately from the more complex task of ranking search results.

End of module assignment · Part A

Code exploration and professional reflection

I compared Python and JavaScript through a small name-cleaning exercise, then considered readability, language choice and professional responsibility. The report describes normalising case, whitespace and title punctuation before removing duplicates, retaining the first spelling and sorting by the normalised key.

For the five variations of “Dr. Smith” in the demonstration, the revised scripts produced one entry. I used this example to discuss how seemingly small processing rules affect data quality, reviewability and accountability. The result is limited to a narrow sample: matching normalised names does not establish that records belong to the same person. Python’s case folding and JavaScript’s lowercasing can also differ on international text. The Python source is shown below; I still need to retain the revised JavaScript implementation alongside it for a reproducible comparison.

End of module assignment · Part B

Ethical and security challenges of AI

In my ten-slide presentation, I considered how AI applications bring ethical and security risks alongside their benefits. I organised the discussion around bias, privacy, transparency and human agency, followed by threats such as data poisoning, adversarial attacks and misleading synthetic content. Recruitment and data-misuse case studies provided examples for the discussion.

I connected these risks to governance, human oversight, secure development and ongoing monitoring. The central argument was that trust depends on addressing ethics and security throughout development and use. This was a literature-based overview: it did not test an AI system or establish that a particular safeguard was effective. My next step is to link each risk to a specific control and a way to evaluate it.

03 / What · So what · What next

Reflective review

Looking back at my coursework using the departmental three-question framework.

What?

I explored five representations of the same sample name: “Dr. Smith”, “Dr.Smith”, “Dr Smith”, a trailing-space version and an uppercase version. My Python script creates a canonical key, keeps the first original spelling and sorts the output. I also compared language choices and examined the wider responsibilities of computing professionals.

So what?

In Part A3, I connect code quality with accountability. A small matching rule can change which records a system treats as distinct, so readable transformations and explicit assumptions matter. My exercise also has limits: a shared normalised name is not proof that two records concern the same person. A production system would need additional identifiers and careful handling of international names.

What next?

My next steps are to extend testing beyond the demonstration input to Unicode, whitespace, punctuation and invalid values, and keep an audit trail of transformations. I also need to separate name cleaning from identity matching and keep both language implementations with their expected outputs so that I can reproduce future comparisons.
