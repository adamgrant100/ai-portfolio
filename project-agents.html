Design and limitations

What the comparison shows.

A deliberately small baseline

The greedy agent looks at adjacent cells and takes a free move only if it strictly reduces Manhattan distance: horizontal separation plus vertical separation. Ties prefer east, south, west, then north. It has no memory or backtracking; if every available move increases distance, it stops.

This is a local rule-based agent, not greedy best-first search. It is intentionally limited so its failure is inspectable.

A route before movement

A* has the complete obstacle map. It ranks candidate states by distance travelled plus Manhattan distance to the goal. Ties prefer lower remaining distance, then lower row-major cell ID. Four-direction movement costs one per step; diagonal moves are forbidden.

Under these assumptions the heuristic is consistent, so A* returns a shortest route when one exists. Its state count includes search work beyond the final route.

Information is part of the result

Both algorithms use the same world, endpoints and movement rules, but A* uses global map information while the baseline only inspects its immediate neighbours. This illustrates planning and information access together; it does not isolate the benefit of either.

The world is static and fully reliable. There are no moving obstacles, unknown cells, battery costs, uncertainty or learning. Three designed scenarios demonstrate behaviour, not general performance.

Where I could take this next

  • Add breadth-first search to compare search effort with another shortest-path method.
  • Give both agents the same limited visibility and measure replanning.
  • Generate seeded random worlds and report success rates across many trials.

These are possible extensions to the current prototype, which uses the three scenarios above.
